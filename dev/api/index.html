GradPower.runpf! — Function
runpf!(psys; verbose=false, fdiff=false, enforce_q_limits=true,
       max_q_outer=50, q_tol=1e-6)

Same as runpf but writes the solution back into the PowerSystem in place.

Generator reactive limits (enforce_q_limits)

With enforce_q_limits=false (the default before v0.3) a PV bus holds its scheduled voltage no matter how much reactive power that takes. The solution is then a fixed point of the power-flow equations but not necessarily a physical operating point: machines can be left absorbing or producing far outside their nameplate QT/QB.

That is not a cosmetic problem. On ACTIVSg2000, 200 of 432 generators solve outside their limits (one bus absorbs 279 MVAr against an 8 MVAr floor). The excess reactive flow drags 20 machines past their pull-out angle – internal angle delta - angle(V) above 90 degrees, where dP/ddelta < 0 – which puts 18 non-oscillatory unstable eigenvalues into the linearised dynamics. Any transient run from that point diverges regardless of the disturbance. On ACTIVSg70k, 470 machines start above 150 degrees and one at 179.5 degrees slips a pole after a fault; its unstable mode amplifies solver round-off by about 2x per step, so trajectories depend on the Newton tolerance.

With enforce_q_limits=true (the default, and uqgrid's default) we run the standard outer loop:

  1. Solve the power flow with the current PV/PQ assignment.
  2. For each bus that started as PV, compare the reactive dispatch against the sum of its generators' limits. If it is above the aggregate qmax (below qmin), convert the bus to PQ, hold every generator there at its own qmax (qmin), and release the voltage.
  3. Repeat until an iteration converts nothing, or max_q_outer is reached.

Pinning each generator at its own limit is exact rather than a heuristic: a bus sits at its aggregate limit precisely when every machine on it is at its own.

Conversion is one-way, as in MATPOWER's default enforce_q_lims = 1. Allowing a pinned bus back to PV once its voltage recovers past setpoint is tempting and is what enforce_q_lims = 2 does, but on ACTIVSg2000 it cycles: a handful of buses pin, release, and re-pin forever, and the loop exits on the iteration cap with those buses still violating. One-way conversion is monotone – every iteration either pins at least one more bus or stops – so it terminates, and when it stops no PV bus is outside its limits. The cost is mild conservatism: a bus can stay pinned when it could have held its voltage after the rest of the system moved.

The slack bus is never limited – it has to absorb the system mismatch, and capping it would leave the power flow with no degree of freedom to close on. If the slack ends up outside its limits that is a property of the case, and verbose=true reports it.

Buses whose only generation is a StaticGenerator stub are switched here too, but note the stub regulates voltage with unlimited reactive power during the transient regardless – the limit is respected by the operating point, not by the dynamics.

Limits come from the .raw generator records (QT/QB, converted to the system base at parse time). Records that carry the usual +/-9999 placeholder simply never bind. Cases built without limit data default to +/-Inf, so enforce_q_limits=true is a no-op for them rather than an error.

Pinning every violator at once can make the re-solve diverge: on ACTIVSg2000 at perturbed dispatches several hundred buses violate together. When that happens the loop backs off and pins only the worst half of them, and so on down to one. If even that one does not converge, or the initial solve does not, runpf! throws a PowerFlowError and the system keeps its last converged solution. (It used to write the diverged voltages back as if solved.)

Returns the number of buses left pinned at a limit.

Parameter and operating-point edits

Parameter edits are CPU-only and between runs, never during integration. Operating-point edits require power flow followed by a new dynamic problem and initialization; existing problems and GPU/batch layouts must be recreated.

set_parameter!(dp, sys, device_index, name, value)
set_parameter!(dp, sys, model, bus, id, name, value; numbering=:external)

Edit a native device parameter between runs. Synchronizes the device struct, dp.pvec, and its CPU table snapshot. The edit survives subsequent initialize_dynamics! calls. Names and units match get_parameter.

Initialization-derived parameters (controller references, static-generator setpoints and load admittances), load powers, and wiring selectors are read-only. GradPower.integrate! — Function
integrate!(dp, ps, tf; dt=1/120, solver=:monolithic, linear_solver=KLUBackend(),
           newton_tol=1e-10, jacobian_reuse=true, predictor=true, ...) -> (tvec, traj)

Integration of the DAE from dp.zvec to tf with fixed step dt.

integrator = :backward_euler (default) or :crank_nicolson (trapezoidal rule on the differential equations, z_{k+1} = z_k + dt/2 (f(z_{k+1}) + f(z_k)), algebraic equations enforced at t_{k+1}; second order away from events). Events and their dt = 0 algebraic re-solves are the same for both; a CN step after an event starts from the re-solved state. CN is not available with limit_method != :none (the limit equations are backward-Euler).

jacobian_reuse=true keeps the Jacobian factorization across Newton iterations and time steps (modified Newton) and refactors only when convergence slows down, at events, or after a failed solve; see JacobianReuse. predictor=true starts each step from the linear extrapolation 2 z_k - z_{k-1} (not across events). Both converge to the same newton_tol; set both to false for full Newton from the previous state. They apply to solver=:monolithic and :schur; :schur_gmres and limit_method != :none always use full Newton.

Output

By default the full trajectory is returned: traj[:, j] is the state at tvec[j], for every step. To store less:

  • save_every = s stores the steps 1:s:nsteps+1 (step 1 = initial state); the final step is not added when it is not on that grid. tvec holds the stored times.
  • save_idxs stores only those rows of the state (traj[r, j] = z[save_idxs[r]]); default : (all rows).
  • save_eltype = Float32 stores in that element type.
  • result = true returns a SimulationResult with named state accessors and metadata. The default remains (tvec, traj). scenario_ids may supply a one-element vector identifying this run.
  • step_callback(k, t, z) is called after the initial state (k = 1) and after every accepted step k = 2, …, nsteps+1, with the full state z at time t, whether or not it is stored. z must not be modified.

Early termination

stop_condition(k, t, z) -> Bool is evaluated after every accepted step k = 2, …, nsteps+1 (after step_callback, before that step's events). When it returns true the integration ends at t: dp.zvec is set to that state and the output holds the stored steps up to it (tvec[end] <= t; with save_every > 1 the stop step itself is stored only if it is on the grid). The caller's condition records why it stopped. z must not be modified.

At an event step the stored (and passed) state is the one before the event's algebraic re-solve. These options do not change the computed solution; dp.zvec is always set to the final state.

GradPower.integrate_batched! — Function
integrate_batched!(bl, ps, tf; dt=1/120, newton_tol=1e-10, linear_solver=KLUBackend(),
                   jacobian_reuse=true, predictor=true, threaded=true) -> (tvec, trajs)

Integrate the bl.M scenarios of bl (each with its own initial state bl.z[m, :] and parameters bl.p[m, :]) through the events registered on ps. Every scenario runs the same Newton solve as integrate! with solver=:monolithic, so a scenario's trajectory equals integrate! with the same z, p and options. Scenarios run on Threads.nthreads() threads when threaded=true. integrator is :backward_euler (default) or :crank_nicolson, as in integrate!. Returns trajs[m], the (sys_dim, nsteps+1) trajectory of scenario m; the final states are written back to bl.z.

save_every, save_idxs and save_eltype select the stored output as in integrate! (same for every scenario). step_callback(m, k, t, z) is called for scenario m with its state after the initial state (k = 1) and after every accepted step; with threaded=true it runs on worker threads, concurrently for different m, so it must only touch per-scenario data. result=true opts into SimulationResult; scenario_ids supplies unique labels in scenario order (default 1:bl.M).

GradPower.SimulationResult — Type
SimulationResult(times, trajectories, channels; scenario_ids, status, events,
                 metadata, storage)
integrate!(dp, ps, tf; result=true, ...)

Named simulation output. Integrators retain their tuple return by default; result=true opts in. trajectories is a matrix for a single simulation or a vector of matrices for batched simulations. Rows follow channels, columns follow times. Arrays are not copied. storage is an optional caller-owned storage handle; no file ownership or automatic closing is implied.

status is one symbol per scenario (:success or :terminated for the built-in CPU integrators). Failed solves still throw and do not return partial results. events describes applied scheduled events, not merely requested events. Tuple destructuring (times, trajectories = result) is also supported.

Events

GradPower.ContingencyEvent — Type
ContingencyEvent(bus, rfault, ton, toff; xfault=0.0)

Shunt fault at internal bus bus, active for ton <= t < toff, with fault impedance rfault + j xfault (pu), i.e. admittance y = 1/(rfault + j xfault) to ground. xfault = 0 (default) is the resistive fault y = 1/rfault. rfault >= 0 and xfault must be finite and not both zero: a bolted fault (zero impedance) is not representable; use a small impedance instead. The GPU integrators support xfault = 0 only.

GradPower.LoadStepEvent — Type
LoadStepEvent(device_idx, t, scale)

At time t, set the ZIPLoad psd.devices[device_idx] to scale times its INITIAL value (the p it had when the integration started): constant-power P, Q and the constant-impedance G, B all scale, so the total load at nominal voltage scales by scale. GradPower.JacobianReuse — Type
JacobianReuse(enabled; rho=0.1, max_stale=6)

Modified-Newton state shared by the Newton solves of one integration.

When enabled, a Newton iteration reuses the factorization of the last Jacobian, across iterations and time steps, and refactors only if

  • there is no factorization for the current dt (first step; event re-solves at dt = 0 and the step after them),
  • the residual norm fell by less than 1/rho since the previous iteration,
  • max_stale iterations of the current solve have used one factorization.

A solve that fails with reuse is retried from its initial guess with a fresh Jacobian every iteration (full Newton), so reuse cannot make a step fail that full Newton solves. dt is the step size of the current factorization (NaN when there is none).
